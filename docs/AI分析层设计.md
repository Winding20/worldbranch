# AI 分析层设计（BYOK · 用户自带模型）

> 定稿约束：**AI 能力建立在用户自己的 API Key 上，不绑定任何单一厂商。**
> 记录日期：2026-10-27

---

## 1. 为什么这条约束重要

它不只是"省服务器成本"，而是决定了三件事：

1. **产品形态**：WorldBranch 是一个工具，不是一个代管 AI 的服务。用户付费给自己的模型商。
2. **架构形态**：模型调用必须走**适配层**，核心引擎不能出现任何厂商 SDK 的硬编码。
3. **数据边界**：用户的 Key 与对话内容不应无条件经过我们的服务器中转（按部署方式区分）。

---

## 2. 分层设计

```
┌──────────────────────────────────────┐
│ 分析任务（Analysis Task）             │  引擎产出的确定性上下文
│  例：解释某次粮荒的成因与传导          │
└───────────────┬──────────────────────┘
                ▼
┌──────────────────────────────────────┐
│ 提示构建（Prompt Builder）            │  只负责"把事实整理成材料"
│  世界资料 + 事件 + 因果链 + 数据可信度 │  不含任何厂商格式
└───────────────┬──────────────────────┘
                ▼
┌──────────────────────────────────────┐
│ 模型适配层（LLM Adapter）             │  唯一的厂商相关代码
│  openai_compatible / anthropic / ...  │
└───────────────┬──────────────────────┘
                ▼
┌──────────────────────────────────────┐
│ 用户配置的 Provider                   │  base_url + api_key + model
└──────────────────────────────────────┘
```

**关键原则**：适配层之上不出现任何厂商名；适配层之下不出现任何业务逻辑。

## 3. Provider 配置

### 3.1 统一配置项

| 字段 | 说明 |
|---|---|
| `name` | 用户自定义名称，如「我的 DeepSeek」 |
| `kind` | 适配器类型：`openai_compatible` / `anthropic` / `gemini` |
| `base_url` | 接口地址，如 `https://api.deepseek.com/v1` |
| `api_key` | 用户自己的 Key |
| `model` | 模型名，如 `deepseek-chat` |
| `enabled` | 是否启用 |

### 3.2 为什么先做 `openai_compatible`

绝大多数国内厂商与本地推理都兼容 OpenAI 的 `/chat/completions` 协议：

- DeepSeek、Kimi（月之暗面）、通义千问、智谱 GLM、MiniMax、百度千帆
- Ollama、vLLM、LM Studio 等本地部署

一个适配器就能覆盖它们，其余厂商按需再加。

## 4. Key 的存放

三种方案，按部署阶段选择：

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 服务端加密存储**（默认） | 存进 `llm_providers` 表，用 `.env` 里的 `SECRET_KEY` 派生密钥加密 | 自己部署、单人使用 |
| B. 浏览器本地保存 | Key 只存在 localStorage，每次请求随 body 带上 | 多用户 SaaS、不想托管 Key |
| C. 环境变量 | 只配一个默认 Provider | 开发调试、CI |

**当前阶段采用 A**，并在表里保留 `owner` 字段，将来加用户体系时不用改表。

安全要求（必须做到）：

- 数据库里**不存明文**；
- 接口返回**脱敏**后的 Key（只显示后四位）；
- 日志里**不打印** Key 与完整请求体；
- 调用失败时，错误信息里不能回显 Key。

---

## 5. AI 在系统中的职责边界（重申）

设计文档已确定：**AI 不产生世界状态**。

| AI 可以做 | AI 不可以做 |
|---|---|
| 解释某次事件的成因 | 决定粮价涨多少 |
| 归纳影响链与传导路径 | 生成未发生的历史 |
| 对比两个分支的差异 | 修改地区数据 |
| 用自然语言回答用户提问 | 替代规则计算 |

因此 AI 层的输入必须**完全来自引擎已记录的事实**：事件、因果链、快照、
`data_quality` 标注。提示词里要明确告知模型"只能基于给定材料回答，
缺数据就说不知道"，并把可信度标注一并传给它。

---

## 6. 失败与降级

- **未配置任何 Provider**：AI 功能整体隐藏，其余功能不受影响；
- **调用失败/超时**：明确提示"模型调用失败"，而不是编一段分析顶上；
- **超时**：默认 60 秒，可配置；
- **限流**：按 Provider 做简单节流，避免用户自己的额度被脚本打爆。
