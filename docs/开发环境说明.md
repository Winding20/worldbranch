## 2. 沙箱带来的三个坑（及解决办法）

当前会话运行在 DSH 的 **workspace-write 沙箱**下，工作区 ACL 由 DSH 自动设置。实测有三处影响开发：

### 坑 1：`os.mkdir(path, 0o700)` 创建的目录无法写入

`tempfile.mkdtemp()` 内部就是用 `0o700` 建目录，因此 **pip、pytest 的 `tmp_path`、venv 的 ensurepip 都会直接失败**（`PermissionError`）。默认模式的 `os.makedirs()` / `os.mkdir()` 不受影响。

**解决**：使用 `tools/pyshim/sitecustomize.py`。它把 Windows 上本就无意义的目录 `mode` 参数丢掉（NTFS 靠 ACL 继承），并让目录 `chmod` 变成空操作。

用法（每个新终端都要设）：

```powershell
$env:PYTHONPATH = "B:\新项目开发\tools\pyshim"
```

或直接用现成脚本 `tools/dev-env.ps1`（推荐）：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
. B:\新项目开发\tools\dev-env.ps1
```

> 注意：本机 PowerShell 的执行策略禁止直接运行未签名脚本，所以必须先做那行 `Set-ExecutionPolicy -Scope Process`（只影响当前窗口）。
> 脚本文件必须以 **UTF-8 带 BOM** 保存，否则 PowerShell 5.1 会按 GBK 解析中文导致语法错误。

### 坑 2：npm 默认缓存目录在沙箱外

`npm install` 报 `EPERM ... \AppData\Local\npm-cache\_cacache\tmp\...`。

**解决**：把缓存指到工作区内。

```powershell
npm install --cache "B:\新项目开发\.npm-cache"
```

### 坑 3：无法删除工作区内的子目录

工作区根目录上有 `Everyone:(CI)(DENY)(S,DC)`（DSH 有意设置），导致沙箱内**删不掉目录**（文件可以删）。`rmdir`、`git clean -fd`、`Remove-Item -Recurse` 都会报 Access denied。

**解决**：需要清理目录时，单独申请一次更宽权限执行；日常开发尽量避免依赖删目录的操作。

## 5. 关于沙箱与「完全权限」

上述坑 1、坑 2、坑 3 都源于沙箱限制，不是工具本身的缺陷。若把会话切到 **完全权限（full access）**：

- pip / pytest / venv / npm 全部按常规方式工作，不再需要 shim 与自定义缓存；
- 可以正常删除目录、执行 `git clean` 等清理操作。

shim 方案的好处是不用改安全设置，代价是每个终端要设一次 `PYTHONPATH`，且删目录仍需单独申请。两种方式不冲突，可随时切换。
