## 0.0 定位调整（v2.0）

**v1.0 的定位**是"一个能模拟任何世界的通用引擎"。实施后发现两个问题：

1. **通用引擎最难证明价值**——"这个引擎能干什么"不是用户的问题；
2. **广度摊薄了可信度**——规则通用到什么都能算，也就什么都算不准。

**v2.0 的定位**：**安史之乱模拟器**——给定真实的历史起点，你改一个决策，看历史怎么分叉，
重点在"因果是否经得起推敲"。

由此产生的取舍：

| 项 | v1.0 | v2.0 |
|---|---|---|
| 范围 | 任意世界 | 只做安史之乱八年（755–763），做深做透 |
| 内容 | 通用规则 + 唐朝数据包 | 人物、官职、军队、州郡、史实年表即核心资产 |
| 质量标准 | 规则自洽 | 推演结果在**史理**上说得通 |
| 用户的问题 | 这个引擎能干什么 | **如果我当时那样做，会怎样** |

v1.0 的通用能力（粮食—财政—民变链条、多尺度、分支对比、AI 分析）
作为**引擎基线**保留在 tang_750 世界，用于回归验证；但不作为产品方向继续扩展。

### 史实不等于剧本

v2.0 最重要的机制：**史实事件带前提**。

```python
{"key": "tongguan_falls",
 "conditions": {"region_held": "tongguan", "character_alive": "geshu_han"},
 "divergence_note": "潼关未失，长安暂安。",
 "source": "《资治通鉴》卷二一八"}
```

- 前提成立 → 按史载发生；
- 前提不成立 → 记为「改道」，并写明**为什么这段历史没走到那一步**；
- 带 `fork` 的事件 → 时间暂停，把决定权交给用户，选完再继续。

这样，"如果潼关不出去野战会怎样"这个问题是可以真的被推演、而不是被叙述的。

## 1. 项目概述

### 1.1 一句话定位

WorldBranch 是一个**多尺度空间、多层级事件、跨区域因果关联**的世界模拟系统：地图负责让用户观察世界，模拟引擎负责推动世界变化，事件系统负责把局部变化与宏观格局连接起来。

### 1.2 不是普通聊天机器人

AI 在项目中承担的是「检索、理解、分析、解释」，**不是**靠生成故事代替模拟。世界状态的变化必须由模拟引擎与规则计算得出，AI 的叙述不能作为事实来源。

### 1.3 项目阶段目标

第一阶段优先做**开箱即用的完整基础世界**，让一个世界真正跑起来：可运行、可推演、可分支、可复现。

## 2. 核心设计理念

| 编号 | 理念 | 状态 |
|---|---|---|
| P1 | 通用模拟引擎：支持不同类型的世界，不局限于唐朝 | 已确定 |
| P2 | 宏观与微观并存：世界、国家、地区、势力、人物可相互影响 | 已确定 |
| P3 | 统一时间推进：同一时间点可发生多处干预，统一结算 | 已确定 |
| P4 | 多尺度地图与事件：缩放影响信息展示层级，事件沿因果向宏观/微观展开 | 已确定 |
| P5 | 统一模拟精度：一个世界使用同一套精度设置，不支持按地区单独设置 | 已确定 |
| P6 | AI 辅助分析：AI 负责分析、推断、总结，状态变化由引擎和规则控制 | 已确定 |
| P7 | 资料与模拟分离：历史资料提供背景知识，结构化数据描述当前状态，规则计算变化 | 已确定 |
| P8 | 不编造数据：无可靠数值时记录未知/估算值，标注来源与可信度 | 已确定 |
| P9 | 模拟精度独立于地图缩放：看哪里与算多细是两回事 | 已确定 |
| P10 | 精度提升不得破坏一致性：不得凭空出现没有依据的历史细节 | 已确定 |

### 2.1 模拟价值定位（已确定）

**选择 C：两者兼顾。**

- 有现实依据的世界（如唐朝）：尽量尊重史实与数据，规则有依据，结果符合现实规律；
- 虚构世界：允许自由设计，但必须遵守其自身明确、一致的规则。

### 2.2 世界的基础构成（四要素缺一不可）

| 组成 | 解决的问题 | 示例（唐朝） |
|---|---|---|
| 知识库 | AI 知道什么 | 制度、历史事件、人物关系、农业与军事知识 |
| 世界数据 | 当前世界是什么状态 | 地区人口、粮食储备、军队规模、财政状况 |
| 模拟规则 | 条件变化后会发生什么 | 粮食短缺如何影响价格，税收如何影响财政与民生 |
| AI 分析 | 如何理解和解释结果 | 分析粮食危机通过贸易、财政、政治产生的连锁影响 |

> 注意：知识库丰富 ≠ 模拟能力强。AI 知道唐朝历史背景，不代表能准确计算某一假设下的粮价变化；它还需要初始数据与明确的计算规则。

## 3. 双线基础结构（已确定）

项目基础分为两条线，AI 作用于两者之间。

### 3.1 第一条线：知识与数据体系

- 收集、整理、标注来源；
- 建立可检索、可关联的知识资料；
- 不同世界使用不同的**知识包**。

### 3.2 第二条线：模拟与计算体系

- 把需要计算的变量、规则、约束、相互作用转化为可执行逻辑；
- 让模拟真正运行起来、可复现、可验证。

### 3.3 AI 在两条线之间的职责

检索知识、理解用户意图、辅助分析因果关系、解释模拟结果。

### 3.4 可扩展性

唐朝需要历史知识；未来社会需要科技与社会发展资料；虚构文明使用用户自定义设定。知识包化设计让新世界可以复用同一套引擎。

## 4. 多尺度地图与事件系统

### 4.1 四级观察尺度（概念设计，非最终界面）

| 层级 | 观察对象 | 展示内容 |
|---|---|---|
| 世界级 | 多个国家或整个文明世界 | 战争、国际联盟、重大贸易变化、全球性灾难 |
| 国家级 | 国家内部及与他国关系 | 政权变化、全国性改革、重大叛乱、经济危机 |
| 地区级 | 省、州、行省或历史地区 | 地方战争、粮食危机、贸易路线中断 |
| 局部级 | 城市、城镇、村庄与重要人物 | 局部事件、人物决策、具体冲突 |

四个层级是**同一个世界的不同观察尺度**，不是四张互不相关的地图。

示例：唐朝世界级地图看到唐朝与周边政权关系 → 放大到河北看到当地军政势力 → 再放大到某座城市才显示具体人物与局部事件。

### 4.2 事件层级判定（已确定原则）

事件**不能**只有固定的「大事/小事」标签。每个事件必须记录：

- 影响范围（空间、涉及对象）
- 影响程度
- 持续时间
- 涉及对象
- 因果关系

系统根据当前视角筛选事件，必要时把多个相关事件归纳为一个上层事件。

示例（河北局部冲突）：

- 局部视角 → 一场具体军事冲突；
- 国家视角 → 若多地区响应并影响朝廷财政，上升为全国性军事危机；
- 世界视角 → 若进一步改变多国力量平衡，才成为国际格局变化的一部分。

反向示例：全国性改革在国家视角是重大事件，在局部视角则展开为某地的税收变化、人口迁移和人物经历。

### 4.3 跨国与跨区域因果关联（已确定）

国家不是地图上的色块，它们之间存在真实的数据关系：

- 贸易依赖与资源流动；
- 外交关系与联盟；
- 战争、军事压力与边境安全；
- 人口迁移与文化传播；
- 技术传播与经济竞争。

影响传导示例：

> 某地区粮食减产 → 影响粮食出口 → 影响贸易伙伴价格与财政 → 引发外交摩擦

系统必须记录这条**影响链**，让用户不仅看到「发生了什么」，还能追踪「为什么会发生」。这些影响必须由模拟规则和数据支持，不能仅凭 AI 叙述认定因果。

### 4.4 三个必须区分的维度

地图缩放层级、事件重要程度、模拟计算精细程度是**三个独立维度**：

- 放大地图不凭空创造历史事件；缩小地图不使局部数据消失；
- 系统按观察尺度聚合或展开信息，同时保留底层数据与事件关联；
- 即使只看世界级地图，底层模拟仍可继续运行；
- 不必在所有地方、所有时间都模拟到人物级别，可按规模与需求采用不同精度。

## 5. 模拟精度系统（已确定）

### 5.1 定位

「世界模拟精度」是核心设计原则：用户像选择模型的推理程度一样选择世界的模拟程度。

**关键区别**：它不是让 AI「想得更深入」，而是真正改变模拟引擎运行的细节、计算量和事件呈现方式。

### 5.2 四档精度（概念定义）

| 档位 | 计算范围 | 说明 |
|---|---|---|
| 1. 宏观推演 | 国家、地区、势力之间的关系 | 人物与局部事件以统计数据体现 |
| 2. 标准模拟 | 宏观系统 + 重要地区、主要势力、关键人物 | 追踪主要事件的影响链 |
| 3. 精细模拟 | 增加地方经济、人物关系、局部冲突与更多事件细节 | 保留更细的因果记录，计算负担较高 |
| 4. 深度模拟 | 在支持的世界和规则范围内模拟更多个体行为、局部交互与复杂事件演化 | 计算负担最高 |

### 5.3 三条原则

1. **模拟精度 ≠ 地图缩放**：可看整个世界同时选精细模拟，也可放大到城市却选宏观模拟。地图决定「看哪里」，精度决定「算多细、记多细」。
2. **精度越高 ≠ 每步调用更多 AI**：底层数值计算仍由程序与规则完成。提高精度意味着启用更多模拟模块、更多实体交互、更细时间步长、更详细事件记录。AI 按需分析与总结。
3. **精度调整不破坏一致性**：从宏观切到精细时，不能凭空出现无依据的详细历史。系统需明确哪些数据已计算、哪些此前被简化、补充细节用了什么假设。

### 5.4 精度设置范围（已确定）

**统一设置**：同一世界只使用一套精度，不允许按地区单独设置。理由：减少地区间数据协调成本，便于验证结果，降低开发与测试复杂度。此决定适合项目初期。

### 5.5 成本控制

提高精度会增加计算负担，系统必须允许用户设置模拟速度、计算预算与细节范围，不承诺任何世界都可无限精细模拟。

## 6. 时间推进与结果呈现（已确定：两套机制分离）

### 6.1 核心区分

- **模拟推进频率**：引擎内部计算的时间步长；
- **结果呈现频率**：多久向用户展示一次结果。

用户控制的是后者。

### 6.2 呈现选项（示例，具体以后可调）

| 选项 | 适用场景 |
|---|---|
| 每月呈现 | 频繁查看事件，适合战争、政变等局势快速变化阶段 |
| 每季度呈现 | 兼顾变化细节与信息密度 |
| 每年呈现 | 重点观察国家格局、经济发展与长期趋势 |
| 重大事件时呈现 | 战争爆发、政权更迭等符合条件时提前展示 |

### 6.3 关键设计：不把时间段当黑盒

即使用户选择「每年看一次」，这一年也不能整体丢给 AI 总结。引擎仍按自身规则推进时间、处理事件、更新状态；系统暂存期间变化，到呈现时点统一输出年度报告、重要事件、数据趋势。

### 6.4 待定

重大事件提前通知时，是否暂停模拟、等待用户干预 —— **待定**（见第 9 章）。

## 7. 世界资料导入与世界构建

### 7.1 像 RAG 一样导入，但不能等同于 RAG（已确定方向）

RAG 解决「AI 从哪里找到相关知识」；模拟引擎还需要知道「世界当前是什么状态，以及这些状态如何变化」。

### 7.2 统一世界资料导入系统（四步）

1. **导入资料**：历史文献、设定文档、表格、人物资料、地图数据等；
2. **建立可检索知识库**：整理资料、提取实体与关系、记录来源；
3. **构建初始世界状态**：把可确认的时间、地区、人物、势力、资源、关系转换为引擎可用数据；
4. **连接模拟规则**：启用适用规则，检查数据完整性、矛盾与缺失参数，再开始模拟。

### 7.3 唐朝世界导入示例

| 维度 | 内容 |
|---|---|
| 时间信息 | 模拟从哪一年开始 |
| 空间信息 | 地区、城市、交通路线 |
| 人物与势力 | 重要人物、政权、官僚机构、军事势力 |
| 经济与社会 | 人口、农业、税制、贸易 |
| 历史事件 | 发生过什么，彼此关系 |

### 7.4 数据质量原则（已确定）

- 历史资料通常无法提供所有精确数值；
- 数值缺失时**不得编造**看似准确的数字；
- 应记录为「未知」或「估算值」，标注来源与可信度，允许用户确认假设；
- 真实历史可帮助 AI 理解背景，但模拟分支一旦偏离史实，原始记录**不能**再作为新世界的未来事实——它只能提供背景知识，不能替代引擎计算。

### 7.5 不做重复维护（已确定原则）

不要让用户分别维护 RAG 知识库、世界资料和大量初始参数。统一到一个世界资料体系，由不同模块使用：

| 模块 | 职责 |
|---|---|
| AI 分析模块 | 检索和理解资料 |
| 世界状态模块 | 保存当前世界结构化数据 |
| 模拟引擎 | 计算变化 |
| 事件系统 | 记录模拟过程中实际发生的事情 |

### 7.6 用户自建世界（已确定：后续）

两种方式可共存，但第一版重点不同：

- **第一版**：提供若干可供选择的完整基础世界，用户开箱即用；
- **后续**：用户从零手动搭建世界、逐步补充资料（世界编辑器）。

理由：单人开发，先把一个世界做成完整体验，避免同时解决「通用引擎 + 世界编辑器 + 用户自定义规则」三难题。

### 7.7 「完整基础世界」的判定标准（已确定）

每个内置世界必须包含：起始时间、地图、地区、主要势力、人物、基础数据、适用规则 —— 而不只是一个背景介绍。

> 先做好一个有代表性的世界，比准备十个只有背景、无法真正模拟的世界更有价值。不需一开始准备几十个世界。

## 8. 第一个基础世界的选择（建议：唐朝）

### 8.1 三个候选方向

| 候选 | 特点 | 风险 |
|---|---|---|
| **唐朝世界**（推荐） | 涵盖国家治理、地方势力、人口、农业、贸易、战争、外交，适合验证多地区、跨势力推演 | 史实数缺口多，需大量估算标注 |
| 现代国际世界 | 现实数据来源丰富，围绕国家、经济、贸易、资源、国际关系 | 需处理敏感现实事件与持续变化的数据 |
| 架空文明世界 | 可自由设定国家、资源、制度与历史 | 需自行设计一套合理规则，缺少现成数据 |

### 8.2 推荐理由

唐朝世界最能检验当前最重视的能力：多地区同步模拟、人物与势力交互、跨区域影响、时间推进、历史分支。

状态：**建议倾向唐朝，尚未最终定死**（见第 9 章）。

## 9. 技术架构

### 9.1 现有技术栈（已选定，不推翻）

Python、Flask、Vue 3、MySQL、Agent / Tool Calling、pytest、Git / GitHub。

### 9.2 分类清单

#### 第一类：现在必须具备

| 领域 | 选型 | 职责 |
|---|---|---|
| 前端与地图 | Vue 3 + 地图组件库 + 图表库 | 缩放、地区选择、事件展示；人口/经济等指标趋势 |
| 后端与模拟引擎 | Python + Flask | 时间推进、状态更新、事件处理、分支管理、模拟计算 |
| 数据存储 | MySQL | 世界配置、人物与势力、地区关系、规则版本、模拟事件、历史状态、分支记录 |
| 工程质量 | Git / GitHub + pytest | 测试多地区同时变化、分支隔离、时间推进、规则计算、结果复现 |

#### 第二类：需要重点研究的新技术

| 技术方向 | 学习重点 | 参考 |
|---|---|---|
| 模拟建模与规则引擎（**最核心**） | 状态机、离散时间推进、事件调度、实体交互、规则校验、因果追踪 | Mesa（Python 智能体建模框架），先评估不决定 |
| 地图与地理数据 | 地图图层、缩放级别、地理边界数据、GeoJSON、跨尺度区域聚合 | Leaflet 等交互式地图方案；地图展示与模拟逻辑分离 |
| RAG 与知识工程 | 文档解析、检索、向量搜索、来源引用、实体关系提取、知识冲突处理 | 按实际数据规模再选向量数据库 |
| 时间线、快照与分支 | 保存某刻世界状态、从历史节点创建独立分支、记录规则版本、比较两条时间线差异 | 项目区别于普通 AI 聊天应用的重要技术 |

> 知识工程的重点不是知识库无限大，而是 AI 能找到正确资料，并区分史实、估算和模拟假设。

#### 第三类：暂时不引入

| 技术 | 何时再考虑 |
|---|---|
| Celery、Redis 等后台任务基础设施 | 模拟运行时间变长，需要后台执行与任务队列时 |
| 大规模多智能体系统 | 规则引擎无法满足具体模拟需求时 |
| Neo4j 等图数据库 | 复杂关系查询成为明显瓶颈时 |
| Kubernetes、微服务 | 项目规模与部署需求确实需要时 |
| 用户自定义代码沙箱 | 创意工坊进入实际开发阶段时 |

### 9.3 技术优先级（研发顺序）

| 优先级 | 内容 | 要证明的事 |
|---|---|---|
| 第一优先 | 数据模型 + 模拟引擎 | 世界可按规则推进时间，多个地区相互影响，结果可保存、可复现 |
| 第二优先 | 地图 + 事件系统 + 时间线 | 模拟结果清晰呈现，可查看不同尺度、追踪事件、比较分支 |
| 第三优先 | 知识库 + AI 分析 | AI 基于世界资料和实际模拟记录解释结果，而非用生成故事代替模拟 |

> 优先级指研发顺序，不代表知识库不重要。知识资料可从第一阶段开始整理，但不必一开始就建成庞大的 RAG 系统。

## 12. 术语表

| 术语 | 含义 |
|---|---|
| 世界（World） | 一个可独立模拟的设定宇宙，含地图、势力、人物、数据与规则 |
| 知识包（Knowledge Pack） | 某个世界专属的资料与知识集合 |
| 世界状态（World State） | 某一时间点的结构化数据快照 |
| 模拟引擎（Simulation Engine） | 按规则推进时间、更新状态的计算核心 |
| 规则（Rule） | 变量之间可执行的作用关系 |
| 事件（Event） | 模拟中实际发生的状态变化记录，带范围、程度、时长、对象、因果 |
| 影响链（Impact Chain） | 从初始变化到跨区域/跨国结果的事件传导路径 |
| 分支（Branch） | 从某历史节点分岔出的独立时间线 |
| 模拟精度（Precision） | 引擎计算与记录的细化程度，全世界统一 |
| 呈现频率（Presentation Cadence） | 多久向用户展示一次结果 |

## 附录 A：讨论中形成的核心原则摘要

1. 知识库丰富不等于模拟能力强 —— 需要知识、数据、规则共同构成基础。
2. 四要素缺一不可：知识库、世界数据、模拟规则、AI 分析。
3. 地图是观察世界的窗口，模拟引擎推动变化，事件系统连接局部与宏观。
4. 事件不应只有大小标签，而应记录范围、程度、时长、对象、因果。
5. 模拟精度与地图缩放相互独立。
6. 提高精度不等于每步多调 AI；数值计算交给程序与规则。
7. 精度提升不得制造凭空的历史细节。
8. 同一世界统一精度，便于管控与验证。
9. 缺数据就标注未知/估算与来源，绝不编造精确数字。
10. 先做好一个世界，再扩展更多世界。
11. 先研究模拟引擎，再堆功能。
