# 部署说明

> **本项目默认就在本机跑，不需要服务器。**
>
> 双击 `start.bat`（Windows）或 `./start.sh`（Linux/macOS）即可，
> 数据存在本地 SQLite 文件里。日常使用不需要看这份文档。
>
> 下面这些内容只在一种情况下有意义：你想把同一份东西放到一台服务器上，
> 让别人通过网址访问。**注意：`deploy/deploy.sh` 从未实跑验证过**
> （开发机连不上目标服务器的 22 端口），首次使用请逐行看输出。

## 1. 三种部署形态

| 形态 | 数据库 | 适用 |
|---|---|---|
| **A. 全部在服务器，SQLite**（最省事） | 数据就是服务器上的一个文件 | 单机对外提供服务 |
| B. 全部在服务器，MySQL | 服务器本地 MySQL（`127.0.0.1`），不开 3306 | 多人并发写入较多时 |
| C. 代码在本机、库在服务器 | 公网 MySQL，需开 3306 并限 IP | 不推荐 |

形态 A 更安全：数据库完全不暴露公网，安全组一条规则都不用加。

## 2. 服务器准备（Linux / 宝塔）

```bash
# 系统依赖
yum install -y python3 python3-devel gcc   # 或 apt install python3 python3-dev build-essential nginx

# 项目目录
mkdir -p /www/wwwroot/worldbranch
cd /www/wwwroot/worldbranch
```

需要上传的内容：

```
backend/        后端源码（不含 instance/、.env）
frontend/dist/  已构建的前端产物（仓库里就有）
tools/          可选，运维脚本
```

> `frontend/dist` 已经随仓库提交，服务器上**不需要装 Node**。

## 4. 配置

```bash
cp backend/.env.example backend/.env
vi backend/.env
```

形态 A 的 `.env`：

```
# 默认就是 SQLite，这一行可以完全不写：
# WORLDBRANCH_DATABASE_URL=sqlite:///instance/worldbranch.db
#
# 要用 MySQL 时（先 pip install -r requirements-mysql.txt）：
# WORLDBRANCH_DATABASE_URL=mysql+pymysql://worldbranch:密码@127.0.0.1:3306/worldbranch?charset=utf8mb4
WORLDBRANCH_DEBUG=0
```

建库（只需要建库和账号，表由代码创建）：

```sql
CREATE DATABASE worldbranch CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'worldbranch'@'localhost' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON worldbranch.* TO 'worldbranch'@'localhost';
FLUSH PRIVILEGES;
```

初始化：

```bash
cd backend
export FLASK_APP=run.py
python -m flask init-db
python -m flask seed          # 世界 + 知识库
```

## 5. 用 serve.py 跑起来

`backend/serve.py` 是生产入口（waitress，Windows / Linux 通用），
和开发用的 `run.py` 分开：不开调试、不热重载、多线程。

```bash
cd /www/wwwroot/worldbranch/backend
HOST=127.0.0.1 PORT=5210 THREADS=8 python serve.py
```

- `THREADS=8`：并发线程数；引擎按请求计算，不需要跨进程共享状态；
- 只监听 `127.0.0.1`，由 Nginx 转发；
- 启动时会检查 `WORLDBRANCH_DEBUG`，若开着会打印警告（会泄露 SQL 与调试信息）。

若偏好 gunicorn，也可以：
`gunicorn -w 2 -b 127.0.0.1:5210 --timeout 120 "run:app"`。

systemd 服务（开机自启）：

```ini
# /etc/systemd/system/worldbranch.service
[Unit]
Description=WorldBranch
After=network.target mysql.service

[Service]
User=www
WorkingDirectory=/www/wwwroot/worldbranch/backend
Environment="FLASK_APP=run.py"
ExecStart=/www/wwwroot/worldbranch/.venv/bin/gunicorn -w 2 -b 127.0.0.1:5210 --timeout 120 run:app
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now worldbranch
```

## 6. Nginx 反向代理

```nginx
server {
    listen 80;
    server_name your-domain.com;

    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:5210;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 120s;
    }
}
```

> AI 分析走请求头传 Key，务必启用 HTTPS，否则 Key 在链路上是明文。

## 8. 本机开发与服务器的切换

只改 `.env` 一行：

| 场景 | 连接串 |
|---|---|
| 数据库放到另一台机器 | `mysql+pymysql://用户:密码@数据库主机:3306/worldbranch?charset=utf8mb4` |
| 服务器本机 | `mysql+pymysql://worldbranch:密码@127.0.0.1:3306/worldbranch?charset=utf8mb4` |
| 单元测试 | 不配置，自动回退到 SQLite |

代码不需要改动。

## 9. 一键部署（仓库里已备好脚本）

| 文件 | 作用 |
|---|---|
| `deploy/deploy.sh` | 在本地执行：跑 CI → 构建前端 → rsync 到服务器 → 远端装依赖/建表/播种 → 重启服务 → 健康检查 |
| `deploy/worldbranch.service` | systemd 单元，放在 `/etc/systemd/system/`，用 `serve.py` 起服务 |
| `deploy/nginx.conf` | 反向代理配置，静态资源由 nginx 直接发 |
| `tools/check_api.py` | 部署后自检：健康检查、前端入口、世界/知识库/分支接口逐项确认 |

```bash
chmod +x deploy/deploy.sh
./deploy/deploy.sh user@your-server /www/wwwroot/worldbranch

# 部署完再验一次（也可随时对着本机跑）
python tools/check_api.py https://your-domain
```

`check_api.py` 只做只读检查，不会改数据；任何一项失败即以非 0 退出。

> **实测范围**：`serve.py` + `check_api.py` 已在本机验证通过
> （waitress 起服务 → 8 项接口自检 → 51 项渲染断言全过）。
> `deploy.sh` 依赖 SSH，本机 22 端口不通，**尚未实跑**，
> 首次使用请逐行看输出，按实际路径与用户名调整。
